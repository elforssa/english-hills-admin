## Implementation

105 atomically replaces only the existing enqueue/finish signatures. Missing, expired, replaced and already-finished ownership returns `PT409` / `crm_reconciliation_lease_lost`; enqueue checks ownership before disabled watermark or inactive mapping, which have their distinct fixed conflicts. Finish permits only the two approved new configuration diagnostics in its existing five-minute other-error branch. No target deliberate `40001` remains. All other database errors retain their identity; there is no catch-all exception conversion.

The actual server wrapper uses a pure exact RPC/code/message classifier that discards raw details/hints. The worker ends an enqueue lease-loss pass without finish, pagination, retry or reclaim; finish loss ends the pass after its single attempt. Confirmed earlier discovered/enqueued counts survive. Provider, missing-secret, timeout/network, invalid-data and storage paths remain separate. Scheduler shape and independent durable job processing remain unchanged.

Catalog acceptance compares every public/crm_security function before/after upgrade. Only the two allowed bodies change; owners, ACLs, SECURITY DEFINER, search paths, argument names/types/defaults and return types are identical. All public table data and cron configuration are identical across the stateful upgrade. Existing lease fences, connection-before-state locks, claims, queue uniqueness/revival, watermark and scheduling intervals remain intact. Product invariants and security permissions do not change; their durable documents need no policy rewrite.
