# Security and permission boundaries

## Adopted S1 credential security boundary — 2026-10-05

[S1 invariants](../architecture/plans/crm-meta-lifecycle-credential-simplification.md#permanent-security-invariants), owner-adopted through PR #93 / main `284c2fe32014f8f3011ac6677ddfe99b0a16ca22`, retain dedicated C2/Employee/dataset, least privilege across capability/tier/tasks/scopes/effective authority, no DQA, human-only handling and Vercel Production-only sensitive custody. The sole active [Gate-B credential runbook](../architecture/plans/crm-h3-s1-gate-b-credential-runbook.md) uses one final token and one bounded supported diagnostic validation, plus safe revocation/replacement. No token value enters AI, source, logs, screenshots or intermediate persistent storage; runtime resolves only the server secret reference.

Credential/activation evidence lives in [CURRENT_STATE](CURRENT_STATE.md) and the [Gate-B closeout](../architecture/evidence/crm-h3-s1-gate-b-closeout-2026-10-05.md). Gate B requires focused independent contract review and explicit credential/Production operational authority. Gate C still requires separate final live review/owner approval. H3-06/07/08 remain outside the credential runbook. Historical Rev7 procedures are retired; [original security chronology](../architecture/history/security-rules-before-outcome-1.md) preserves their approval scope. No security boundary is changed by this navigation cleanup.

In the advisory implementation, deferred pending-stop retrieval is director-only through `crm_list_pending_lifecycle_stops`; anonymous/service API execution and all other roles are denied, and direct marker/audit table access stays closed. Responses contain only opaque CRM scope IDs and coarse intent/reason/time, never request/actor details, proof answers, provider matching IDs or contact values. Trusted resolution must commit actual later-source safety stops under its preheld exclusive identity barrier, and unhanded pending acquisition exclusions cannot start an audit-erasure clock. See the [findings remediation evidence](../architecture/evidence/crm-r4-advisory-implementation-2026-10-01.md#independent-review-findings-remediation--2026-10-01).

Authorization is not sidebar visibility. UI, page route, server/API/RPC and RLS/database must agree. Middleware skips API role gating so each handler must authenticate itself. The middleware matcher exempts only static assets, image optimization, the same-origin Sentry tunnel (`/monitoring`) and Vercel's `/_vercel/` platform prefix (Speed Insights); application routes, including look-alike paths, stay gated and [middleware tests](../../scripts/test-middleware-security.mjs) prove it. Real-user monitoring events are stripped of query, fragment and record IDs in both URL and route in the browser ([filter](../../src/lib/rumScrub.mjs)), and the reporter passes an explicitly scrubbed route; the real beacon is checked by the owner after deployment. Database role is authoritative; client input and editable Auth metadata are not role proof. Never broaden RLS or remove checks/tests merely to make frontend access work.

## H3-02 transport boundary

The [approved H3 multipart contract](../architecture/plans/crm-h3-technical-readiness.md#authentication-compatibility-and-proof) adds the dedicated outbound token only to the transient multipart form immediately before HTTP. Frozen payloads, query strings, persisted data, logs and error output must remain token-free; no simultaneous bearer authentication or manually supplied multipart boundary is permitted. Fixed Graph host/path, redirect rejection, no-store, eight-second timeout, bounded response handling and no uncertain replay remain. H3-02 changes no ACL, RLS, privacy or sharing-stop boundary and provisions no credential. [Implementation evidence](../architecture/evidence/crm-h3-02-implementation-2026-10-02.md); current release evidence is in [CURRENT_STATE](CURRENT_STATE.md).

### Enrollment at payment (migration 127, released 2026-11-05)

[Plan EAP-r4](../architecture/plans/enrollment-at-payment.md), [ADR-015](../architecture/decisions/ADR-015-enrollment-at-payment.md); **released on 2026-11-05:** PR #182 (merge `3788132…`) with `127_enrollment_at_payment.sql`, applied on Production and checked read-only and with rolled-back reception and `anon` probes ([closeout](CURRENT_STATE.md#enrollment-at-payment-migration-127-production-closeout-r0r4--2026-11-05)). No role gains a capability and no RLS policy changes.

- **Retired-status guard.** Trigger `enrollments_retired_status_guard` (function `academic_security.guard_retired_enrollment_status()`, SECURITY DEFINER, fixed `search_path`, no API grant) raises `23514`, hint `eap.status_retired`, on any insert or update **into** Submitted, Under Review, Trial or Rejected, for every role, `service_role` and the migration role included. The only exemption is the two transaction-local flags `eh.membership_sync` and `eh.enrollment_command` both `on`, used by the journalled archive revert (the Batch D pattern).
- **« Inscrire et encaisser » for prospects.** `public.crm_enroll_and_collect(p_request_key uuid, p_data jsonb)` is SECURITY DEFINER with a fixed `search_path`, executable by `authenticated` only (revoked from `public`, `anon`, `service_role`), and requires both the CRM reader check and `manage_finance_operations` (reception, admin, director). It runs `crm_start_enrollment` (Confirmed only) then `create_charge_payment` in one transaction. The payment idempotency key is derived on the server from the caller and the CRM request key (`sha256('eap:payment:' || uid || ':' || key)`), never taken from the client. On a first run without a receipt or a free enrollment it raises `22023`, hint `eap.payment_required`, rolling back the enrollment, the lead link, the conversion and the cancelled tasks; a replay of a committed call returns the original ids without re-checking; a call without `payment` succeeds only when the server finds the linked enrollment already paid; « Autre » is refused (`eap.program_not_enrollable`). It adds no conversion path.
- **`crm_start_enrollment`** keeps its body except that `initial_status` must be Confirmed and `group_id` is refused; its `authenticated` execute grant is **revoked**, so no API role can call it directly.
- **Closed creation paths.** `create_enrollment` always refuses; `save_enrollment_changes` refuses a status change (`egc.status_not_permitted`); the pre-enrollment branch of `save_receptionist_enrollment` refuses (its group-assignment branch on Confirmed/Validated rows stays); `portal_request_reenrollment` refuses; `create_public_registration` refuses (`eap.public_registration_retired`; its `service_role`-only grant kept) and `/api/public/inscription` answers **410** before reading the request (origin, rate limit and Turnstile are no longer consulted; the Turnstile secret, the website proxy secret and `/api/public/crm-inquiry` are untouched). `reopen_enrollment` refuses a row the archive step ended (`eap.archived_not_reopenable`) unless that archive was reverted.
- **Placement.** `academic_security.place` and `public.place_learner_in_group` are re-created from their 120 bodies (SECURITY DEFINER, fixed `search_path`, the `assign_group` check kept) with a last parameter `p_without_enrollment_reason`. A receptionist places only a Confirmed/Validated enrollment of the group's programme and year (`23514`, hint `eap.paid_enrollment_required`); director/admin need that dedicated reason of 1–200 characters (`eap.placement_reason_required`) to place a learner without one, or on a legacy unpaid row, separate from the capacity-override reason; such placements are logged as `placement_without_enrollment` with the reason and author role. The private core has no API grant; the public command is executable by `authenticated` only (revoked from `public`, `anon`, `service_role`, as in 120).
- **Director « Contrôles ».** `get_finance_review_queue` stays director-only; `pending_confirmation` is replaced by `unpaid_never` and the informational `paid_unlinked`, both through the private `finance_security.unlinked_payment_count` (no API grant).
- **Archive step support.** `maintenance.eap_archive_journal` (ids, statuses and actions only, no personal data) has RLS enabled and no API privilege. `crm_security.protect_enrollment_link` admits one exemption, under the transaction-local flag `eh.crm_detach`: clearing `enrollment_id` of a non-converted lead whose enrollment is Ended or Rejected, learner kept. Conversion fields stay immutable. The archive step (`supabase/manual/enrollment_at_payment_archive.sql`) ran on Production on 2026-11-05 as the migration role through the guarded transport (14 enrollments ended, 1 lead detached, no conversion). Its revert (`supabase/manual/`) and the restore script (`scripts/rollback/127_enrollment_at_payment_restore.sql`) were not run; each needs its own approval.

### Courses with dates (migration 128, released 2026-11-06)

[Plan CDC-r3](../architecture/plans/course-dates-close.md), [ADR-016](../architecture/decisions/ADR-016-course-dates-and-close.md); **released on 2026-11-06** (PR #186, merge `ec1319c…`; [closeout](CURRENT_STATE.md#courses-with-dates-migration-128-production-closeout-r0r4--2026-11-06), with the rolled-back role probes). No role gains a capability other than the director commands below.

- **Director commands.** `list_courses_to_close`, `close_course_preview`, `close_course`, `reopen_course` and `close_school_year_preview` are SECURITY DEFINER with `search_path = pg_catalog, pg_temp`, executable by `authenticated` only (revoked from `public`, `anon`, `service_role`), and refuse every role but director. Conflicts raise `PT409` (ADR-009), never `40001`. The private helpers (`academic_security.course_*`, `year_close_rows`) have no API grant.
- **The closed mark** (`groups.closed_at`, `closed_by`) is written only inside the commands, under the transaction-local flag `eh.course_command`; a direct write is refused for every role, `service_role` and the migration role included (`42501`, hint `course.mark_protected`). A closed group's dates, year, programme, level and capacity are frozen.
- **Closed-course guard.** Trigger `enrollment_course_guard` (`academic_security.guard_course_placement()`, SECURITY DEFINER, no API grant) share-locks the group row (and the online course row) and refuses any entry into a closed course on every path (`23514`, hint `course.closed`). - **Journal.** `maintenance.course_close_journal` (ids, statuses, groups, years and charge ids; no personal data) has RLS enabled and no privilege for `public`, `anon`, `authenticated` or `service_role`.
- **Family-scoped group read (OA3).** The policy « groups read all auth » is replaced by « groups read staff » (every authenticated non-pending, non-family role, as before) and « groups read family » (parent and student: only `public.family_group_ids()`, a SECURITY DEFINER helper with a fixed `search_path`, executable by `authenticated` only, returning the groups of the caller's visible learners). « groups admin all » is unchanged. Group names must never contain a learner's name (One-to-One names are neutral).
- **Known limitation (R3-1).** The lock order is proven through `place`, or a direct write of a learner the command does not hold; a direct API update of `enrollments.group_id` for a learner a close already holds can still deadlock with it (pre-existing; the application never writes that column directly).

### E-mail links that work (released 2026-11-14)

[Plan ELW-r3](../architecture/plans/email-links-that-work.md), [ADR-017](../architecture/decisions/ADR-017-auth-links-verify-on-click.md); released 2026-11-14 (PR #190, merge `87ab19e…`; [closeout](CURRENT_STATE.md#e-mail-links-that-work-release-closeout-r0r3--2026-11-14)). No role, policy or database function changes.

- **Public path `/auth/confirm`** (middleware `PUBLIC_PATHS`). It accepts only `token_hash` (1–200 of `[A-Za-z0-9_-]`) and `type` in `invite`, `email`, `magiclink`, `recovery`; it takes no destination parameter. Response header `Referrer-Policy: no-referrer`; `noindex`. Every Auth e-mail template links here, built from Site URL.
- **Rule L1 — no verification on load.** No request made on load carries `token_hash`: not the page, not the middleware, not the shared session provider; a visitor without a session causes no Auth request. Only the button verifies (`verifyOtp`). `/inscription-compte` follows the same rule.
- **Activation mark.** An account counts as activated when its own `profiles.full_name` is not blank, written only by the activation form; the role is not used for that decision. The new-password form exists only right after its recovery link was verified, on that page; after it, other sessions are signed out (D5).
- **No account disclosure.** The sign-in-link and reset forms, and the used-link screen, give the same answer whatever the address. `shouldCreateUser: false` stays.
- **Token hygiene.** The token is removed from the address bar after Auth answers and is scrubbed from Sentry (relative paths included) and speed monitoring; it does appear in Vercel's request log, which stays owner-only.
- **Supabase Auth configuration (Production, owner-only):** Site URL `https://admin.english-hills.com` (no trailing slash); Redirect URLs keep `/login/callback` and `/inscription-compte`; templates are the files in `supabase/templates`.

### Online room header — whiteboard sources (PR A of online classroom tools; implemented on a pull request, not merged as of 2026-11-15)

Plan [online classroom tools](../architecture/plans/online-classroom-tools.md) (OCT-r3, D2 and the S1 decision of 2026-11-15), amending OL-r6 A6/A7 ([ADR-008 amendment](../architecture/decisions/ADR-008-online-learning-pilot.md#amendment--whiteboard-sources-on-the-room-path-2026-11-15)). These rules hold once the pull request is merged; until then `main` has the OL-r6 header.

- **Only `/online/room/*`.** The catch-all Content-Security-Policy and every header outside the room path stay byte-for-byte as they are ([header test](../../scripts/test-online-headers.mjs)).
- **Exactly two whiteboard sources**, in `script-src` and `style-src`: `https://us04st1.zoom.us/web_client_whiteboard/` (Production key) and `https://us05st1.zoom.us/web_client_whiteboard/` (development key). Path-scoped; never a wildcard; a third host, or a host change by Zoom, needs a new owner decision before the list in [next.config.mjs](../../next.config.mjs) changes.
- **`blob:` only in `connect-src`** (added), `media-src` and `worker-src` (as before). **Never in `script-src`.** `worker-src` stays `'self' blob: https://source.zoom.us`. No wildcard in `script-src`, `style-src` or `worker-src`.
- **Room trace.** `[online room] … csp blocked directive=… host=… source=…` prints the directive, the host (or the scheme, for `blob:`; the keyword, for `eval` and `inline`) of a refused address and the host of the script that asked, never a path or a query; the trace as a whole prints display labels, connection reasons, directive names and hosts only.
- **No eval on the room path; one named refusal.** `script-src` of the room path has no `'unsafe-eval'` and gets none without a new owner decision. Zoom's whiteboard program probes for it and works without it, so exactly one refusal is expected while a whiteboard loads (owner decision of 2026-11-16): directive `script-src`, blocked value `eval`, raised by a script under an approved whiteboard source (`https://us04st1.zoom.us/web_client_whiteboard/` or `https://us05st1.zoom.us/web_client_whiteboard/`). The trace marks it `expected=whiteboard-eval-probe`. Any other refusal, and this one from any other source, is a failure of [the classroom script](../../scripts/test-online-zoom-classroom.mjs) and of the Production test.
- **Whiteboard powers.** Starting and stopping a whiteboard is decided by Zoom from the signed role in the pass. What the page offers by role (teacher exports, learner does not) is presentation, not a boundary. Room pages exchange three fixed texts on Zoom's command channel: the presenter's page sends `eh-whiteboard:open` and `eh-whiteboard:closed`, and a participant who arrives or reconnects sends `eh-whiteboard:ask`, which only the presenter's page answers. A receiving page believes « open » and « closed » only from the host or a manager, as Zoom lists them, and uses them only to show or hide one line.
- **Raise hand (« Lever la main », PR D, owner decisions of 2026-11-17).** Room pages exchange markers with the prefix `eh-hand:` on the same channel: `raise`, `lower-self` and `raised:<seconds>` (the answer to `ask`; a whole number, 0–10800) act only on the hand of the sender Zoom names; `lower` (sent to one learner) and `lower-all` are believed only from the host or a manager, as Zoom lists them; a payload without a numeric sender id and any other text are ignored. The markers carry nothing about a person; the trace says `hands total=<n>` and `hand state=… by=…` only. Who sees the panel follows the pass's role (presentation); who may lower another's hand follows Zoom's list (the boundary). No attendance, database or server effect.

### Online passes — newest connection wins (reliability PR; released 2026-11-19, migration 129)

Plan [online room reliability](../architecture/plans/online-room-reliability.md) (ORR-r2, section 1, decisions D2, D10 and D15 of 2026-11-18). In force since the release of 2026-11-19: migration 129 applied to Production at 11:05:53 UTC and PR #200 deployed as `4a6bada` ([release record](../architecture/plans/online-room-reliability.md#release-record-r-p0r-p3--2026-11-19)); the live switch stays off outside supervised test lessons. *(Heading until the closeout: « implemented on a pull request, migration 129 not applied, not merged as of 2026-11-17 ».)*

- **Supersession at confirmation only.** `online_issue_join` supersedes nothing; it takes `issued_at` after the per-lesson lock and records the course's provider on the pass. `online_confirm_pass(p_jti)` (authenticated, `security definer`, fixed `search_path`) answers only for a pass whose `profile_id` is the caller and, under the same per-lesson lock, supersedes the same person's earlier-issued current passes of that lesson (person: the learner for a learner pass, the teacher for a host pass, the account for an observer pass) only when the caller's own pass is current and its holder still qualifies. A superseded pass is refused by `online_resolve_join` (`online.superseded`).
- **Own pass only.** `online_check_pass(p_jti)` and `online_confirm_pass(p_jti)` refuse any id the caller does not hold with the same `online.forbidden` as an id that does not exist; they return the join evaluation plus booleans and a count, never a provider field (N5). The helper `online_security.own_pass_state` has no API grant.
- **No automatic removal (D15).** The platform never calls Zoom's `removeUser` and has no leftover list: Zoom refuses a removed connection's browser for the rest of the session (code 3009), so a dead device's connection is left for Zoom to drop (about 3 minutes). « Retirer » in the toolkit is the teacher's own act and blocks that browser until the end of the lesson; the room shows the removed text with « Quitter » only.
- **The `eh-room:newer` marker** on Zoom's command channel is one constant text, at most once per 2 s; it decides nothing: the receiving page asks the database.
- **The room's trace** (`[online room] …` console lines in the participant's browser) carries states, counts and reasons only. The pass watcher writes `pass confirm state=…`, `pass state=…` and `pass check state=failed` (#200 review N6): never a pass id, a name or a token. The notice « Vous avez pris la place de … » is shown to a parent only (N2).
- **Status route.** `GET /api/online/status` answers director and admin only (every other caller, signed in or not, is refused), whatever the live switch and the gate say, with words only (« correctes / incorrectes / absentes »): never a credential value, its length, its class of mistake or a fragment. The paste-mistake rule (`credentialShape` in the adapter) closes `onlineGate` with `provider_invalid` and never logs or throws the value.

### Online webhook — evidence only, own gate (webhook PR; implemented on a pull request, migration 130 not applied, not merged as of 2026-11-19)

Plan [online room reliability](../architecture/plans/online-room-reliability.md) (ORR-r2, section 3, decisions D5–D7, D13 and D16). These rules hold once the migration is applied and the pull request is merged.

- **Own gate, independent of the live switch.** `/api/webhooks/online/<provider>` answers only when `onlineWebhookGate` holds: the provider is the configured one; it is not `fake` in Production; its adapter supports webhooks; its credentials and `ONLINE_VIDEO_PROVIDER_WEBHOOK_SECRET` are set and free of paste mistakes. Otherwise it answers 404 having read only the headers. **Kill switch:** remove the webhook secret in Vercel and redeploy. Joins never read that variable.
- **Before any write.** A missing or oversized `Content-Length` (64 KiB) gets 413 before the body is read, and the body is read only up to that bound. Then non-UTF-8 bytes, a bad signature or a timestamp outside 300 s get 401 before any database call. The challenge writes nothing.
- **Writes.** Only through `online_record_join_event` and `online_record_session_event` (service role only). Both are idempotent on their unique keys and capped at 600 rows received in 60 s (`rate_limited`, answered 429). A failed write answers 503, never 200. A session event is stored only when its name is the course's room reference plus the lesson id. Stored fields are fixed: no payload, name or device data.
- **Read.** `online_usage_month` and `online_room_status` are for director and admin only. They and the status route return words, times and counts, never the secret, its length or a fragment. **Events never write or pre-fill attendance** (D7).
- **Retention (D13).** `online_purge_session_evidence()` (no API grant), run monthly by `pg_cron` (`online-evidence-purge`), deletes event and refusal rows older than 12 months.
